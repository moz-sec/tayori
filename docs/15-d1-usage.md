# D1利用量の監視

監視を有効にすると、定期実行時にCloudflare GraphQL Analytics APIからアカウント全体の当日UTCの読み取り行数と書き込み行数を取得する。
対象データベースの容量はD1 REST APIの `file_size` から取得する。監視結果と設定はD1の `app_state` に保存する。
取得値にはCloudflare側の集計遅延があり、上限への到達を事前に完全には防げない。

ビルド時に `TAYORI_D1_USAGE_ENABLED=true` と `CLOUDFLARE_ACCOUNT_ID` を指定する。
本番では `TAYORI_D1_DATABASE_ID`、プレビューでは `TAYORI_PREVIEW_D1_DATABASE_ID` を指定する。
アカウントIDと対象DBのIDは、それぞれCollectorの `D1_ACCOUNT_ID` と `D1_DATABASE_ID` に渡される。
有効化時にこれらのIDが未指定または空白のみの場合、ビルドはエラーになる。
`D1_ANALYTICS_TOKEN` はGraphQL Analyticsと対象D1情報の読み取りに必要な権限を持つシークレットとしてCollectorに設定する。

以下の値は同名のビルド時環境変数で指定し、省略時は表の値を使う。数値の上限と最大経過秒数は正数、警告割合は0より大きく1より小さい数とする。

| 変数                     |    既定値 |
| ------------------------ | --------: |
| `D1_STORAGE_LIMIT_BYTES` | 419430400 |
| `D1_ROWS_READ_LIMIT`     |   3000000 |
| `D1_ROWS_WRITTEN_LIMIT`  |     60000 |
| `D1_WARNING_RATIO`       |     0.875 |
| `D1_MAX_AGE_SECONDS`     |      7200 |

GitHub Actionsでデプロイする場合は、対象の `preview` または `production` Environmentに上記のビルド時環境変数を登録する。
同じEnvironmentのシークレットに `D1_ANALYTICS_TOKEN` を登録する。監視を有効にした場合、シークレットが空ならデプロイ前に失敗する。
閾値の変数を省略すると表の既定値を使う。プレビューと本番はそれぞれ別に設定する。
現在GitHub Actionsは停止中のため、このデプロイ経路での実行は未検証である。

監視は初期状態では無効となる。デプロイ後、設定がD1に保存されるのは次の定期実行時である。
無効状態から有効化した場合、その定期実行まで取り込みは停止されないため、必要に応じて有効化前に収集を停止する。
実行環境で認証情報が未設定の場合、次の定期実行で利用量を確認できない状態となり取り込みを停止する。
空でない不正なトークンなどで取得に失敗した場合、最後に成功した観測値が有効な間はその値で判定し、期限切れまたはUTCの日付変更後に停止する。
設定値が不正な場合も取り込みを停止する。

無料枠はアカウント内の他のデータベースとも共有される。行数はアカウント全体を監視するが、容量は対象データベースのみを監視するため、他のデータベースが使う容量と集計遅延、監視自体の操作に十分な余裕を残して上限を決める。監視1回につき外部APIを2回呼び出し、設定と観測値の保存などにD1の読み書きを使う。通常の定期実行ごとに取得するため、実際の消費量は実行頻度に依存する。

取得失敗後は最後の観測値を保持し、設定した最大経過時間を過ぎると新しい取り込みを停止する。UTCの日付が変わった場合も、当日の観測値を取得するまで停止する。設定上限に達した場合は、上限を下回る新しい観測値が得られると再開する。監視の停止を解除するには、設定と接続権限を確認し、取得が成功することを確認する。保存済み記事は監視によって削除しない。

参照: [D1のメトリクスと分析](https://developers.cloudflare.com/d1/observability/metrics-analytics/)、[D1 API](https://developers.cloudflare.com/api/resources/d1/)。
