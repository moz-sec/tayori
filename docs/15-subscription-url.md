# 購読URLの変更

購読先の設定から「RSS / Atom URL」を変更できる。APIは `PATCH /api/v1/sources/{id}` の `url` を受け付け、登録時と同じHTTP/HTTPS・公開先URLの検証と正規化を行う。別の購読先と正規化後のURLが重複した場合は409を返し、変更を保存しない。

URLの保存では即時取得しない。共通の収集設定に従って次回予定を再計算し、Collectorが定期収集する。一時停止中の購読先は変更後も停止し、再開するとその時点から次の収集境界を待つ。再開だけでは取得失敗後の待機期限を解除しない。新規購読先の登録時の初回取得は従来どおり別途実行する。

URL変更と同時に `generation` を進め、旧URLの未完了ジョブを無効にする。取得中の旧レスポンスも保存時の世代確認で破棄する。ETag / Last-Modified、旧URLのサイト情報・成功失敗の診断と失敗後の待機期限はリセットする。新URLの失敗は通常の購読先の取得状態表示で確認できる。

購読先IDと既存の記事キー・記事・既読・お気に入り・あとで読むは維持する。記事キーは購読先IDとGUID・Atom ID、または記事URL等から算出する。同じキーの配信は引き続き重複排除し、内容の更新でも既読・保存状態を保つ。配信元の移行でGUIDや記事URLが変われば別キーとなり、同じ内容でも新規記事として登録される場合がある。過去キーの再計算や記事の無断統合は行わない。

URL変更と旧ジョブの無効化はD1の同じトランザクションで行う。失敗時は両方をロールバックする。他の購読設定変更と競合した場合は409を返すため、設定を開き直して再試行する。

一覧・登録・更新のレスポンスには購読設定の版 `generation` を含む。URLを含むPATCHでは、編集開始時に取得した版を `expectedGeneration` として指定する。不指定は400、不一致は409とし、他端末で先に保存された変更やジョブを変更しない。URL以外の更新でも `expectedGeneration` を渡せば同じ競合検出を行う。

競合後の一覧再取得は、現在の画面へ結果を適用できた場合だけ成功とする。通信失敗や古い応答の破棄はダイアログ内にも失敗を表示し、古い入力の再保存・購読解除を無効にしたまま、一覧を更新して設定を開き直すよう案内する。
