# 画面・操作仕様

## 1. 情報構造

購読先はサイト/フィード、フォルダは購読先の分類、ボードは記事の分類。1購読先は1フォルダまたは未分類に属し、記事は複数ボードへ保存できる。

## 2. PC画面

```text
┌─────────────────┬──────────────────────────────────────┐
│ Tayori          │ フォルダ名 / 未読件数                │
│ すべて・未読    │ 未読のみ [ON]  表示分を既読          │
│ あとで読む      ├──────────────────────────────────────┤
│ お気に入り      │ 配信元・公開日時                     │
│ フォルダ        │ 記事タイトル                        │
│ ├ 技術          │ 要約                                │
│ ├ セキュリティ  │ 既読 / あとで読む / ☆ / ボード      │
│ └ 趣味          ├──────────────────────────────────────┤
│ ボード          │ 次の記事 …                          │
│ 購読先・設定    │ さらに表示                          │
└─────────────────┴──────────────────────────────────────┘
```

サイドバーはボタンで開閉する。スマートフォンでは画面を1カラムにし、フォルダ一覧をドロワーで表示する。タッチとキーボードの両方で操作できるようにし、フォーカス位置を見える形で示す。ボタンには読み上げ用ラベルを付け、未読とエラーは色だけで区別しない。

## 3. 操作規則

- タイトルを選ぶと元記事を別タブで開き、既読状態の更新も送る。更新に失敗した場合は未読に戻し、通知する。
- 「表示分を既読」は取得済みの最大50記事を対象とする。全履歴を一括変更する曖昧な操作は設けない。
- フォルダ階層を扱えるデータモデルとし、UIでも折り畳み表示する。初期操作は追加・改名・移動・削除。
- フォルダ削除時は子フォルダと所属購読先を親へ移す。記事・購読は削除しない。
- 購読解除は収集停止と非表示化。保存記事は残す。再登録時は以前の購読を復帰させる。
- ボード削除は所属関係のみ削除。ほかの保存指定がなく期限超過なら整理対象になる旨を表示する。
- 未読0件、購読0件、未取得、取得失敗、無料枠による停止は異なる状態として表示する。

## 4. 購読追加・OPML

初期の手動追加はRSS/Atom URLを指定する。一般WebサイトURLからの自動発見は将来対応。

OPMLはブラウザで解析して確認画面を出す。追加候補・既存・不正URL・階層を提示し、ユーザーが実行を選んだ後に小分けで送信する。XMLのDTD/外部実体は禁止。サーバーは正規化された入力を再検証する。

初期の技術的上限案はファイル1MiB、1回の移行200購読先、深さ10、名前100文字。購読総数のプラン制限とは分ける。1リクエスト5購読先以内とし、フォルダは親から先に登録する。中断時は同じファイルから重複せず再開できる。

同じ URL が複数のフォルダにある場合は、最初に見つかったフォルダへの所属を採用し、確認画面に重複を表示する。既存購読のフォルダは自動で変更しない。OPMLには記事、既読状態、ボードを含めない。

## 5. 設定画面

初期は購読先管理、OPML入出力、収集状況、保持ルールの説明を提供。保持日数は「7日固定」と表示し、変更UIは置かない。無料枠向けの内部パラメータは一般ユーザー画面に露出させない。

## 6. ブランド

名称は Tayori。「便りが届く」感覚と、フォルダで整理する落ち着いた使い心地を表す。アイコン候補はリポジトリの `icon/icon_right.png` と `icon/icon_dark.png`。採用するバリエーションは未確定。生成画像で既存アイコンを自動的に置き換えず、小さいサイズや明暗の異なる背景で確認してから採用する。
