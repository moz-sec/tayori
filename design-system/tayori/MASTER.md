# Tayori デザインシステム

Issue [#39](https://github.com/moz-sec/tayori/issues/39) の方針を実装・レビューに使うための正本。日本語で日々の記事を読む個人向けRSSリーダーとして、「便りが届き、フォルダで静かに整理できる」体験を優先する。

ui-ux-pro-max の `minimal content reader` 検索で得られた Minimalism & Swiss Style の可読性・単純な構造を参考にした。検索結果のモノクロ色、ゼロ角丸、LP構成は採用しない。既存daisyUIテーマ、既存アイコン、既存の文字フォールバックを尊重して、frontend-design の情報階層と装飾を絞る指針を適用する。

## 色の正本

実際の値はdaisyUIの `light` テーマにあるOKLCH変数を使う。下表のhexは見本のsRGB近似であり、部品へ直書きしない。

| 役割 | 既存トークン | 見本 |
| --- | --- | --- |
| 記事・ナビ・ダイアログの面 | `--color-base-100` | `#ffffff` |
| 記事列の周囲・管理フォームの面 | `--color-base-200` | `#f8f8f8` |
| 記事間・ナビ境界・管理セクションの区切り | `--color-base-300` | `#eeeeee` |
| 本文・操作ラベル | `--color-base-content` | `#18181b` |
| 主操作・フォーカス・選択の強調 | `--color-primary` | `#422ad5` |
| エラーの面 | `--color-error` | `#ff637d` |

塗りつぶした主操作には `primary-content`、エラー面には `error-content` を組み合わせる。`warning` などの状態色を小さい文字へそのまま流用しない。通常文字は背景とのコントラスト4.5:1以上を基準にし、状態色の組み合わせと既読カードの透明度は [#43](https://github.com/moz-sec/tayori/issues/43) で整備する。

未使用の `.tayori-mark` と独自の緑色は廃止する。採用済みの `/favicon.ico` はブラウザータブ用として維持する。画面内のブランドは「Tayori」の文字で示し、新しいロゴやパレットを追加しない。

## 文字と余白

- フォントは既存の `Inter, "Noto Sans JP", ui-sans-serif, system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif`。端末にない場合はシステムフォントへフォールバックし、Webフォントの外部取得を必須にしない。
- 本文の基準は16px・行間1.5。記事タイトルは20px程度で本文より強く、画面見出しは30px程度。要約は14〜16px、補助情報は12〜14pxを目安にする。
- タイトルは内容、配信元・日時は出典、未読表示は読む順番を伝える。管理用の操作は記事の見出しと同じ強さにしない。
- 欧文本文は1行80文字以内を目安に、日本語も読書に適した行長とする。長い単語の折り返しは [#44](https://github.com/moz-sec/tayori/issues/44) で扱う。

| 余白 | Tailwind基準 | 主な役割 |
| --- | --- | --- |
| 4px | `1` | ラベルと入力、操作列の微調整 |
| 8px | `2` | 関連する操作・入力の間 |
| 12px | `3` | 記事内のメタ情報・タイトル・要約の間 |
| 16px | `4` | モバイルの記事内側、ナビ内側 |
| 24px | `6` | PCの記事内側、ブランドとナビの間 |
| 32px | `8` | 独立した情報群の区切り |

これらの値を部品ごとに増殖させず、既存のTailwind余白スケールを使う。フォルダ階層のインデントや画面外周は用途のある例外とし、コンテンツの階層を伝える役割を維持する。

## レイアウト

記事は左揃えで1列に読む。PCでは幅320pxを基本とする購読ナビと、最大幅を持つ記事列に別々の領域を確保する。モバイルでは記事を優先し、ナビは必要な間だけ開く。

```text
PC（1024px以上）                モバイル
┌──────────┬────────────────┐  ┌────────────────────┐
│ 開閉      │ 記事見出し・操作  │  │ ナビを開く          │
│ Tayori   │                │  │ 記事見出し・操作     │
│ 絞り込み  │ 記事タイトル     │  │ 記事タイトル        │
│ 購読先    │ 出典・要約・操作 │  │ 出典・要約・操作     │
│ 管理操作  │ ────────────── │  │ ────────────────── │
│          │ 次の記事         │  │ 次の記事            │
└──────────┴────────────────┘  └────────────────────┘
```

ブランドの上には開閉操作の領域を残し、固定ボタンと重ねない。サイドバーには影を付けず、境界線で記事領域との関係を示す。記事群は1つの白い面と区切り線でまとめ、各記事へ影やカード全体のhover効果を付けない。タイトルのリンクや操作ボタンが操作対象であることを示す。

領域の重なり、ドロワーの閉じ方・背景操作・フォーカスは [#40](https://github.com/moz-sec/tayori/issues/40) の担当。この文書のレイアウト方針だけで既存の重なりが解消したとは扱わない。

## 部品とインタラクション

- `btn`、`input`、`select`、`checkbox`、`modal-box` 等のdaisyUI部品を使う。角丸の正本は `--radius-field` / `--radius-box`、境界線は `--border`。同じ用途に別の角丸・色を直書きしない。
- 記事は個々の装飾カードではなく、読み進める行の集合として扱う。管理フォームの淡い面は「入力する場所」、ダイアログの面は「今の作業」を区別するために使う。
- 操作はhoverだけに依存させない。キーボードでは `:focus-visible` のprimary色・2pxの輪郭と3pxのオフセットで現在位置を示す。フォーカスを不要な装飾として消さない。
- 非操作のカードに浮き上がるアニメーションを付けない。`prefers-reduced-motion: reduce` ではドロワー・ダイアログ・操作部品の移動や遷移を抑える。
- タッチ領域の拡大と副操作の整理は [#46](https://github.com/moz-sec/tayori/issues/46)、保存トグルと現在位置の読み上げは [#47](https://github.com/moz-sec/tayori/issues/47) で扱う。

## 状態と日本語

未読・既読・あとで読む・お気に入りは、色だけで区別しない。取得中、購読先なし、未取得、未読0件、保存0件、取得失敗は文脈に合う説明と次の操作を持たせる。フォームの失敗は入力のそばに出し、入力を保持する。

| 用途 | 表記 |
| --- | --- |
| ブランド | Tayori |
| ナビの購読一覧 | 購読先 |
| フォルダの追加 | フォルダを作成 |
| 子フォルダの追加 | 子フォルダを作成 |
| フォルダ編集 | フォルダ設定 / フォルダ名 / 親フォルダ |
| フォルダ階層の最上位 | 最上位 |
| 変更確定・中止 | 変更を保存 / キャンセル |
| 購読登録 | 購読先を追加 / 購読先を追加中… |

画面上の文言と読み上げラベルで同じ用語を使う。アイコンだけの操作には、必要に応じて対象のフォルダ名・購読先名を含める。実装用の内部パラメータや技術的な説明を管理画面へ無条件に追加しない。

E2E基盤 [#38](https://github.com/moz-sec/tayori/issues/38) のテストを組み合わせる際は、旧 `New folder` / `Folder settings` / `Folder name` / `Create` / `Save` / `Settings for …` / `追加` のロケーターを上記の日本語へ更新する。購読登録フォームの名前とボタン名はどちらも「購読先を追加」のため、ボタンは `getByRole("button", { name: "購読先を追加", exact: true })` のように役割で区別する。
